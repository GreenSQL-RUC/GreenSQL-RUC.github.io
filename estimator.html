Benchmark Runtime Estimator

Every warm step-up entry pays a restart and a thermal gate, then runs its warm-ups and its measured batches. How long a batch of N copies takes depends on how heavy the query is. Split the single-copy runtime axis into stacked ranges, pick a batch config for each, and the total and where it goes update live.

Defaults measured in the slope sample, 21–23 Sep 2026, on an i5-8350U at 2.5 GHz with PG 18.4 on tpch_idx. The model reproduces measured entries to 0.2 %.

Reference projection

For all of SQLStorm (14 372 passing queries, 2 repeats, 2 warm-ups), this model projects 526 h with {1,16} everywhere, 149 h with the tier 95 % configs, 200 h with the tier 99 % configs, and 869 h with full everywhere. Under 2 J the config barely matters: 6.7–8.3 h whatever it is, and full costs only 1.1 h more there. The page cannot reproduce these on its own, because they need each query's single-copy time. The tier configs come from the error-by-band table on the harness map.
