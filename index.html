GreenSQL Harness Map

How the Makefile, scripts and C runners fit together, what each one reads from the kernel and from PostgreSQL, and where every measured number ends up. Energy comes from Intel RAPL counters; timing and plan statistics come from the wall clock, EXPLAIN ANALYZE and process resource usage. Linux perf counters are not used anywhere.

How the pieces call each other

Everything starts at a make target, which primes sudo, loads the msr module and passes one bundle of environment variables down. Drivers in run/ sequence the work; the compiled runners in bin/ do the measuring. On a narrow screen the figure scrolls sideways.

Where each number comes from

One warm step-up entry, and a zoom into its largest batch. The values are the real ones logged for TPC-H q01 on tpch_idx in run 3 (1.7 GHz, 53 TPC-H queries), the gated run before the slope sample. The anatomy is the same at 2.5 GHz; only the values differ.

Why batches step up from 1 to 16 copies

A batch's energy is E(N) = F + b·N: an overhead F for each psql process, plus a cost b for each copy. Fitting a straight line through the step-up separates them. b is the query's own marginal energy, and F is what a single-copy measurement would wrongly charge to the query.

25.1 Jper extra copy (slope)
1.6 Jper-process overhead (intercept)
9.1 Wpackage power, every size

F is not purely start-up cost. In the slope sample its median is 0.58 J. For 4-worker plans it stays near 0.5 J whatever the query (Spearman ρ(F, E₁) = +0.20). For serial and 0–2-worker plans it grows with the query (ρ = +0.83), from about 0.36 J to about 1.9 J in the 40–75 J band.

A straight line is safe to fit. There were no throttle events at any N, and E(N) is linear (median curvature +0.17 %). Long batches run up to 8 °C warmer (band-median peak 82 °C), which shows only as a +0.18 % curvature in the heavy bands.

In run 3 (1.7 GHz, 53 TPC-H queries), test/thermal_check.py found that a two-point slope from 1 and 16 copies landed a median 0.59 % from the full fit, down from 1.28 % before the thermal protocol. The slope sample (2.5 GHz, 250 SQLStorm queries) instead scores a single repeat against the 10-repeat slope; the table below gives that per band.

How many copies are enough

Each config estimates the per-copy energy b from one repeat. {1} is E₁ alone. {1,N} is (EN − E₁)/(N − 1). EN/N is the plain batch average. full is the least-squares fit over N = 1, 2, 4, 8, 16. The truth is the 10-repeat slope, scored leave-one-repeat-out (median SE 0.18 %). Bands are by single-copy energy E₁, from the slope sample at 2.5 GHz.
